# BerryMark Studio — Installation, Startup, and Author Workflow

Build 02 is a local Chromium application for manuscript inspection, basic document information, screen organization, and source-safe saving. It does not replace the `.berry.md` manuscript with a database or another authoring format.

## Requirements

- Node.js 22 is recommended and is the primary Build 02 verification environment. The package supports Node.js 20 or newer.
- Current Google Chrome on macOS or Chromium on Arch Linux, using Chromium's File System Access API.
- A local checkout of this repository.

No browser extension, database, external host, AI service, or Sanity credential is required. Ordinary editing makes no external service requests.

## Install and launch

From the repository root:

```sh
npm ci
npm run studio
```

The command prints an address such as:

```text
BerryMark Studio is ready at http://127.0.0.1:4173
Open this exact address in Chrome on macOS or Chromium on Arch Linux.
Manuscripts remain on your computer. Press Ctrl+C to stop Studio.
```

Open the **exact printed loopback address**. Keep the terminal running while using Studio and press **Ctrl+C** when finished.

If port 4173 is occupied, either stop the other process or choose another port:

```sh
npm run studio -- --port 4174
```

Studio reports unavailable ports, permission failures, and invalid arguments in the terminal. `npm run studio -- --help` prints the command summary. The server binds to `127.0.0.1`; it does not listen on all network interfaces.

## Create a document

1. Choose **New** or **Create a document**.
2. Enter a working filename ending in `.berry.md`. A Challenge title is optional at this stage.
3. Choose **Create document**.
4. Add a screen and edit basic document information as needed.
5. Choose **Save As** because a new document has no file destination yet.

New documents begin incomplete. Studio does not invent release dates, approval, authorship, Scripture passages, rights confirmations, or other metadata.

## Open a manuscript and its review history

1. Choose **Open**.
2. In Chromium's file picker, select exactly one `.berry.md` manuscript.
3. If its `<manuscript-name>.berry.md.review.json` companion exists, select that JSON file in the same picker. The companion is optional, but source-only opening cannot restore earlier edit-history warnings.
4. Confirm the selection.

Opening does not rewrite the manuscript. Valid and safely incomplete documents are editable. Unsupported or malformed documents remain read-only and retain their original bytes; diagnostics explain the condition.

If the working document has unsaved changes, Studio asks before replacing it. Cancelling leaves the working document open.

## Edit document information

The **Document information** panel supports Challenge title, summary, stable slug, and Challenge type. Choose **Apply document information** after editing. Applying changes updates the working document; it does not write the file until Save or Save As succeeds.

Summary has three explicit states:

- **Authored value** stores text, including an intentionally empty string.
- **Explicit null** stores YAML `null`.
- **Missing** removes the optional summary key.

Publishing, editorial-approval, Scripture translation, and rights values are read-only. Validation does not certify import readiness, theological content, editorial approval, or publication readiness.

## Organize screens

The left navigator shows screens in manuscript order. It supports:

- Selecting a screen to inspect its ordered Content Blocks.
- Adding a screen with a label and optional heading.
- Editing a label or heading while preserving the semantic ID.
- Moving a screen with keyboard-operable **up** and **down** buttons.
- Removing a screen after confirmation.

New semantic IDs are generated by the document engine. Authors do not manage them. Removal and reordering affect only the working document until a save succeeds.

All nine Content Block types have read-only structural cards in Build 02. Expand **Complete interpreted structure** to inspect fields that do not have a specialized visual summary. Full block editing is outside this build.

## Save and Save As

Studio writes two related files:

1. The authoritative `.berry.md` manuscript.
2. Its source-digest-bound `.berry.md.review.json` review companion.

For **Save As**, use **Choose manuscript** and **Choose companion** separately, then choose **Save both files**. Existing non-empty destinations require confirmation. Cancelling a picker or closing the dialog before the final save leaves the working document and existing files untouched.

For an opened document, **Save** reuses the authorized destinations. Studio checks that the manuscript still has the expected source digest before overwriting it. An externally changed, moved, missing, or permission-revoked file produces an error rather than a silent overwrite. Use Save As to choose a new destination after resolving the condition.

A successful message is shown only after both writes, manuscript read-back, companion read-back, and engine reopening succeed. If any step fails, the working document remains marked unsaved. See [the recovery protocol](studio-review-companion.md) before manually altering a prepared companion.

Keyboard shortcuts:

- **Ctrl+O** / **Cmd+O**: Open.
- **Ctrl+S** / **Cmd+S**: Save.
- **Ctrl+Shift+S** / **Cmd+Shift+S**: Save As.

Closing or reloading a dirty browser page also invokes the browser's unsaved-change protection.

## Diagnostics and safe recovery

The Diagnostics panel distinguishes valid, incomplete, unsupported, review, edit, and save conditions with text and severity labels rather than color alone. Engine diagnostics retain source locations when supplied.

Missing, malformed, or mismatched review history never causes Studio to invent approval history or rewrite the manuscript during opening. Replacing that companion during Save requires explicit confirmation. Interrupted prepared transactions have a defined recovery path; do not delete the companion merely because it contains a `prepared` phase.

## Development browser tests

Install the pinned development dependency with `npm ci`, then run:

```sh
# Uses Playwright's installed Chromium by default.
npm run test:browser

# Or select an existing Chromium executable.
BERRYMARK_CHROMIUM_PATH=/path/to/chromium npm run test:browser
```

The tests use in-memory picker handles for browser interactions and failure injection. Real disk encoding and interruption behavior is tested separately by `test/studio-review-state-file.test.js`. See the [verification record](studio-build-02-verification.md) for executed results and remaining manual checks.
